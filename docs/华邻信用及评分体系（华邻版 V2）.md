# 华邻 信用及评分体系（华邻版 V2）

> 在原《客户信用及评分体系》基础上，按华邻真实架构（**去中心化 · AI 驱动 · 极简 · 抢单 · 平台不经手支付 · 站内私信不发联系方式**）重写。
> 核心原则：**只用平台能核实的信号；能观察不到的（尤其支付）一律不进分；负面才设限、"没历史"不设限（防冷启动死锁）。**

## 为什么要改（与原方案的差异及原因）

| 原方案 | 华邻版 V2 | 原因 |
|---|---|---|
| 一个 0–100 综合信用分（认证+履约揉一起） | **拆成两个诚实信号**：口碑分（星级）+ 可信度（徽章+粗档位，精确分仅内部用） | 认证和履约是两回事，揉成一个模糊数字既难解释又招刷分/扯皮；拆开更清晰 |
| 公开精确分数 | **对外只显示徽章 + 粗档位**（优质/良好/🆕新用户/⚠️受限），精确分只在后台用于抢单门槛 | 公开精确数字会让人盯着"为什么掉 2 分"，产生无谓争议与刷分动机 |
| OCR 实名认证 +15 | **不做 OCR**，保留人工/后台认证徽章 | 老板已拍板不上 OCR |
| 信用卡预授权 +10 / 拒付尾款 -20 | **删除所有与支付挂钩的加扣分** | 平台不经手支付，"预授权/拒付"无法核实，记进分里就是假数据 |
| 保险/持牌"后台核验"自动加分 | **改成资质徽章**（用户已可上传资质照） | "逐个人工核验加分"是运营黑洞；徽章足够传递信任 |
| 无冷启动说明 | **新用户默认中性「🆕 新用户」，只对负面信号设限** | 否则新客户发不了单、新师傅抢不了单 → 鸡生蛋死锁 |
| 只有分数 | **AI 口碑摘要**（一行话概括） | 契合 AI 定位，弱化纯数字刷分，更有说服力 |

## 一、口碑分（Reputation · 双向）

### 1.1 双向盲评（核心）
传统平台只让客户评师傅，师傅遇到"恶客/临时加活/拒付"无处申诉。华邻**双向评价**：

- 触发：双方在订单点【确认完工】后，各自弹出轻量评价窗。
- 三档：**差(1★) / 一般(3★) / 很棒(5★)** + 快捷标签。
  - 客户评师傅标签：`准时到达` `技术过硬` `明码标价` `干净整洁` ／ `中途加价` `态度不好`
  - 师傅评客户标签：`付款极速` `描述准确` `非常客气` ／ `临时加活` `恶意挑刺` `沟通困难`
- **盲评防报复**：双方提交前互不可见；**双方都提交** 或 **完工满 48h 系统自动默认「很棒」** 后，评价才同时公开。
  - 原因：防止一方因怕差评而不敢给真实评价；48h 自动好评避免"对方不评就永远不解锁"。

### 1.2 综合星级算法
- 很棒=5.0、一般=3.0、差=1.0。
- **综合星级 = 近 30 单加权平均，偏向近期**（越近权重越高）。
  - 原因：避免早期个别差评永久拖累；反映"当前"服务水平。
- 展示：师傅星级显示在名片墙/名片；客户星级仅以**粗档位**示给师傅（见三）。

## 二、可信度（Trust · 只用可核实信号）

**不再是一个公开的百分数**，而是一组徽章 + 一个粗档位（精确分仅后台用于门槛）。

### 2.1 计入的信号（都能核实）
| 信号 | 方向 | 说明 |
|---|---|---|
| 手机已验证 | 基础 | 短信验证码（已实现） |
| 实名/商户认证徽章 | 加信任 | 人工/后台认证（不做 OCR） |
| 资质/保险徽章 | 加信任（师傅） | 用户上传资质照，展示为徽章，不自动加分 |
| 社媒外链 | 加信任 | 已实现，公域背书 |
| 完工单数（双方确认） | 加信任 | 平台可观察的完工事件（orders/completion 已在） |
| 好评累计 | 加信任 | 来自双向评价 |
| 扣分事件 | 减信任 | 见下，仅限可核实的负面 |

### 2.2 扣分（只记平台能观察到的负面）
| 事件 | 说明 |
|---|---|
| 无故放鸽子 / 临时跳单 | 接单后超时未履约、双方确认失败/超时 |
| 有效投诉 / 仲裁判负 | 走现有 disputes + 仲裁函数判定 |
| 恶意/多次取消 | 频繁取消 |

> **删除**：一切与支付挂钩的扣分（拒付尾款等），平台无法核实。

### 2.3 粗档位（对外展示）
由"可核实信号 - 扣分"映射到档位（精确分只在后台）：
- **🟢 优质**：认证齐全 + 完工多 + 高口碑 + 0 有效投诉
- **🔵 良好**：正常履约
- **🆕 新用户**：暂无足够履约数据（**中性，不设限**）
- **⚠️ 受限**：有有效投诉/多次放鸽子 → 触发门槛（见 2.4）

### 2.4 门槛（只对负面设限，不对"没历史"设限）
- **受限档**：暂停参与「急单抢单」；情节重的限制发单/接单。
- **新用户**：**照常参与**，只是没有加成。
  - 原因：冷启动不能死锁；风险靠"负面才降级"控制，不靠"没历史就锁"。

---

## 三、评分对系统的反哺（契合抢单架构）

1. **师傅端**：星级 + 徽章显示在抢单后的名片墙；**高口碑 + 优质档**获得优先推送。
2. **客户端**：师傅在抢单/接单前，能看到该客户的**粗档位信号**（✅良好 / 🆕新用户 / ⚠️注意：多次临时加活或拒付），据此自行决定是否接单。
   - 只给粗信号、不给精确分：够决策、又不过度监控客户。
3. **AI 口碑摘要**（可选，后续）：从评价标签生成一行话，如「准时、明码标价，30 单 0 投诉」。

---

## 四、防刷分

- 完工须**双方确认**才计数；同一对用户重复刷单降权。
- 盲评 + 48h 窗口本身抑制互吹/报复。
- 加分有节流（如完工加分月度上限）。

## 附：二期 华邻信用分细则（0–100，参照原 PDF 骨架 · 只留可核实项）

> 精确分**只在后台**用于风控与门槛；对外只显示徽章 + 粗档位。封顶 100、地板 0。

### A. 加分项

| 维度 | 加分 | 说明（华邻版调整） |
|---|---|---|
| **基础分**：注册 + 手机验证 | **+30** | 已有 `phone_verified` |
| 实名认证 | **+12** | **后台人工核验**（不做 OCR）（原 15→略降） |
| 常驻地址（选填） | **+5** | 邮编/GPS，选填 |
| 社媒外链绑定 | **+5/平台，上限 +10** | 已有 social_links |
| 【师傅】本地持牌 | **+12** | 后台核验，显示盾牌（原 15→略降） |
| 【师傅】商业责任险 | **+10** | 后台核验，显示高亮盾牌 |
| ~~【客户】支付/定金预授权~~ | ~~+10~~ | **删除**：平台不经手支付，无法核实 |
| **完工单（双方确认）** | **+2/单，月上限 +12，累计上限 +24** | 已有 `orders` completed（原 +1/上限10 → **提高**） |
| **获「很棒」(5★)** | **+1/次，上限 +15** | 来自一期双向评价（原 +0.5/上限10 → **提高**） |

> **为什么提高履约权重**：认证只是"传证件"，履约才是"真本事"。原方案认证类就能到 ~85、履约封顶仅 20，等于埋头做好单不如传几张证。调整后：**光认证 + 基础分约到 79，要冲高分必须持续做好单**；反之没证但口碑好、单量足的师傅也能靠履约攒到 ~69（良好档），更公平。月上限 + 累计上限一起防刷单。

### B. 扣分项（只记可核实负面）

| 事件 | 扣分 |
|---|---|
| 无故放鸽子 / 临时跳单 | **−10/次** |
| 有效投诉 / 仲裁判负 | **−20/次** |

> 「有效投诉」= 走 disputes 且**仲裁判该用户负**（或管理员确认成立）；「严重仲裁判负」= 诈骗/恶意等被判严重。

### C. 粗档位（对外）
- 🟢 **优质**：分 ≥ 80 且 0 有效投诉 且 完工 ≥ 5
- 🔵 **良好**：分 ≥ 50
- 🆕 **新用户**：完工 = 0 且 0 投诉（数据不足，中性，**不设限**）
- ⚠️ **受限**：触发下方门槛

### D. 门槛（按老板 2026-07 拍板，以「有效投诉数」为主）
| 触发 | 后果 |
|---|---|
| **≥ 3 条有效投诉** | 降为 ⚠️ 档，抢单/发单时**提示**，仍可参与 |
| **≥ 5 条有效投诉 或 1 次严重仲裁判负** | **师傅：停止抢单** ／ **客户：限制发单**，直至申诉解除 |
| 🆕 新用户 | **照常参与**，只对负面设限，不对"没历史"设限（防冷启动死锁） |

### E. 反哺
- 师傅：`分 ≥ 85 且 口碑 ≥ 4.8★` → 抢单优先推送。
- 客户：师傅抢单前看到客户粗档位（一期已上线 `client_trust`，二期升级为综合可信度）。
